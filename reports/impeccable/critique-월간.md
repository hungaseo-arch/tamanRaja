## 디자인 특이성 판정

이 제품만의 화면임. 모임 규칙(Winner·Medalist·Host, 1등조·2등조, 기준/당월/차월 핸디)을 표·배지·확인 창에 직접 녹였고 범용 대시보드로 바꿔 쓸 수 없음. 장식 없이 숫자·테두리 중심이라 DESIGN.md의 "잔디 위의 스코어카드"와 맞음.

탐지기(detector) 결과: advisory 2건, 모두 `MonthlyTable.vue` 974·992줄의 `text-[13px]`(핸디 규칙 창). 툴바 13px 예외와 별개 위치이므로 아래 P2 항목으로 올림. 그 외 AI 슬롭 패턴·대비·레이아웃 위반 없음.

## 잘 된 점

1. 변경분 보호가 완결됨. 달 이동(Monthly.vue:40-75), 새로고침 경고(77-84), 취소 시 폐기 확인(MonthlyTable.vue:361-374), 저장 전 요약(284-303). 관리자 실수에 대한 방어가 제품 원칙 4와 일치.
2. 본인 줄의 참석 진입점(MonthlyTable.vue:416-417, 777-784)이 상세 진입점과 다른 시각 언어(실선·초록·달력 아이콘)로 구분됨. 44px 터치 영역을 줄 높이 증가 없이 확보.
3. AttendancePanel의 선택 상태가 색에만 기대지 않음(AttendancePanel.vue:126-133). 체크 아이콘, 라벨, sr-only "선택됨", roving 키보드 지원이 모두 있음. 색만으로 뜻 전달 금지 원칙 충족.

## 우선 이슈

### P1

**[P1-1] 모바일 읽기 모드에서 핸디 값이 표에서 사라짐**
- 위치: `MonthlyTable.vue:743-747`(헤더), `802-811`(셀). `당월 핸디`는 `!isEditing && 'hidden sm:table-cell'`, 기준·차월 핸디는 `hidden sm:table-cell`
- 문제: 제품 목적은 "자기 순위·핸디·참석 확인"인데, 375px 읽기 모드 표에는 회원·스코어·NET·결과만 남음. 핸디 3열이 전부 숨고 이름을 눌러야 상세 창에서 보임. 이름 버튼이 탭 가능하다는 단서는 점선 밑줄뿐(RowDetailButton, 추정). 중장년 사용자가 가장 자주 찾는 숫자(차월 핸디)가 2탭 깊이에 있음
- 영향: 사용자 ID 확인 동선 길어짐, 탭 가능성 발견 실패 시 값을 못 찾음
- 추천: 표에서 `결과 그룹`을 이미 `결과` 셀 안으로 합쳤듯 `차월 핸디`(또는 당월 핸디)를 NET 아래 보조 줄이나 좁은 열로 노출. 이름 셀에 "눌러서 상세" 힌트(첫 방문 한 번) 추가
- 추천 명령: `/impeccable adapt` → `/impeccable layout`
- 공유 자원: `Table*`(`ui/Table`), `RowDetailButton`, `useCompactTable` 영향. 표 구조 변경은 연간 랭킹·나의 기록 표와 공유 패턴이므로 확인 필요

**[P1-2] 편집 모드에서 저장 버튼이 화면에 남지 않음**
- 위치: `MonthlyTable.vue:548-555`(주석: 표제 줄은 sticky 가 아니라 표와 함께 밀려 올라감), `620-636`(저장·취소), `Monthly.vue:323-325`
- 문제: 회원이 많은 달에 점수를 위에서 아래로 입력하면 저장·취소가 화면 밖으로 사라짐. 저장 이유를 막는 메시지(`validationError`, `missingHcNames`, 699-709)도 같은 위치라 입력 중에는 보이지 않음. 모바일 엄지 범위 바깥(상단)이기도 함
- 영향: 저장을 누르려면 맨 위로 스크롤. 저장 실패 사유를 놓침. 입력한 값을 잃을 위험은 없지만 마지막 단계에서 막힘
- 추천: 편집 모드에서만 하단 고정 액션 바(저장·취소 + 오류 한 줄). 툴바의 저장·취소는 유지하되 모바일에서는 바에 위임
- 추천 명령: `/impeccable layout` → `/impeccable adapt`
- 공유 자원: 신규 컴포넌트가 생기면 관리자 화면의 다른 편집 표와 공유 가능. `Layout`의 main 스크롤 구조(`max-w` 금지 규칙, DESIGN.md Layout)와 sticky 충돌 주의

**[P1-3] 점수를 바꾸면 수동으로 고른 조·시상이 조용히 덮임**
- 위치: `MonthlyTable.vue:189-220`(`computeAutoFields`), `257-265`(watch deep), `868-899`(결과 조·시상 select는 수동 변경 가능)
- 문제: 결과 조와 시상은 select로 직접 바꿀 수 있는데, 다른 회원의 점수를 한 칸만 고쳐도 점수가 있는 모든 행의 조·차월 핸디·시상이 다시 계산되어 덮어씀(215-219). 어떤 칸이 자동이고 어떤 칸이 수동인지 표시가 없음. 모바일 편집에서는 결과 조 열이 아예 숨겨져(`hidden md:table-cell`) 저장될 조를 볼 수도 없고, 차월 핸디 열도 숨겨짐
- 영향: 관리자가 Host 지정·조 보정 후 나머지 점수를 입력하면 지정이 사라짐. 저장 전 요약(Winner/Medalist/Host)에서 알아챌 수는 있으나 조·차월 핸디는 요약에 없음. 운영 DB 기록 정확성에 직결
- 추천: 자동 계산값에 "자동" 표시, 수동으로 바꾼 칸은 잠금 표시 후 재계산에서 제외(또는 덮기 전 한 줄 안내). 저장 요약에 1등조·2등조 인원 추가. 모바일 편집에서 최소한 결과 조를 이름 아래 보조 줄로 노출
- 추천 명령: `/impeccable harden` → `/impeccable clarify`
- 공유 자원: 없음(이 컴포넌트 안 로직). `computeResults`(`@/lib/rank`)는 공유이므로 건드리지 않고 호출 측에서 처리

## 페르소나 지적

**회원 "박 선배"(PRODUCT.md 중장년, 스마트폰)**: 라운드 직후 자기 핸디를 보려고 월간 화면을 열었는데 핸디 열이 없음(P1-1). 이름을 눌러야 한다는 단서가 약함. 참석 패널은 큰 핸디 숫자가 먼저 눈에 들어와 질문을 놓침(P2-6). 안내 문구가 단문이라 확인 창에서 멈춤(P2-8).

**Casey(산만한 모바일 사용자)**: 저장·오류 안내가 모두 위쪽. 편집 중 알림이 오면 돌아왔을 때 새로고침 경고는 있어 좋으나 하단 저장 동선이 없음.

**Sam(접근성)**: 참석 라디오·roving·sr-only는 양호. 오류 상태가 빨간 테두리뿐인 점수 칸(P2-4), 도움말 13px(P2-9)이 걸림.
